# Architecture decisions

Short records of decisions and the alternatives that were rejected. Newest last.

## ADR-001: Bundled privileged Binder service; optional Shizuku

Updated after physical testing and the owner's companion-free requirement. The APK includes an `app_process` service bootstrapped through authorized ADB. A DUMP-protected provider additionally checks kernel caller UID; the daemon checks the app caller UID on every Binder method and links app death. The external-provider Android API is required because a standalone shell has no registered application thread. The final Binder route physically executed as UID 2000 on the Fold. No network shell listener is exposed. Both direct and optional Shizuku paths use the same subprocess executor and policy engine; backend selection is explicit. Privilege ends at reboot and requires setup again. Phone-only pairing remains unfinished.

## ADR-002: Gateway is a Cloudflare Worker + SQLite-backed Durable Object

- **Context:** Cloud agents cannot reach a phone on cellular or CGNAT. The Mac must not be in the runtime path.
- **Decision:** The phone keeps one authenticated outbound WebSocket to a Durable Object. MCP clients POST to the Worker, which routes to the device's socket.
- **Why:**
  - The Workers Free plan includes SQLite-backed Durable Objects: 100k requests/day, 13,000 GB-s/day and 5 GB of storage.
  - With the Hibernation API, idle sockets incur no duration charges.
  - It is deployable with `wrangler` and needs no VPS maintenance.
- **Rejected:**
  - Device-hosted MCP endpoint. It is not reachable from the cloud, and exposing it would need port forwarding.
  - A temporary tunnel. It is not durable.
  - A VPS. It works but costs money and needs maintenance; the gateway code is portable enough to rehost.
  - Push-only (FCM). It would need a Firebase project and is best-effort. It remains a possible wake hint later.
- **Consequence:** The gateway sees plaintext requests and results. This implementation persists device/catalog and pairing/OAuth metadata, and correlates bounded in-flight requests. It does not implement a durable offline execution queue or a durable result cache. The phone is the durable request/result authority.

## ADR-003: Official MCP TypeScript SDK v2

The initial hand-written dual-era proposal is superseded. SDK 2.3.1 `createMcpHandler` works in Workers with its Cloudflare JSON validator. Actual v1/v2 clients passed local Worker integration tests; v2 and Grok Bot subsequently called the real phone through the deployed Worker. Keep stateless Streamable HTTP compatibility in the maintained SDK.

## ADR-004: OAuth for hosted clients; private bearer remains supported

The same Worker uses pinned `@cloudflare/workers-oauth-provider` 1.2.3 for authorization-code flow, S256 PKCE, discovery, CIMD/DCR, consent, refresh and resource binding. The phone creates a one-use encrypted pairing invitation and a least-privileged local agent. Actual ChatGPT/Dots consent and phone tool calls completed. Existing private-bearer clients continue to work. The phone authenticates the forwarded agent credential and rechecks its current grant for every operation and accepted approval. Display names never identify or merge principals. Consent expiration is resolved with a fresh browser session/code, without relaxing CSRF protection.

The gateway remains trusted: it handles the forwarding credential and plaintext results, so it can impersonate that credential within the phone's existing grant. End-to-end agent signatures are not implemented. Token lifetimes and phone grant lifetimes are separate; revocation on the phone remains authoritative.

## ADR-005: Framework SQLite instead of Room

- **Decision:** Use `SQLiteOpenHelper` with explicit versioned migrations.
- **Why:** The schema is small: requests, events, agents, skills, automations and key-value settings. This avoids annotation processing (KSP) with AGP 9's built-in Kotlin and keeps compare-and-set updates explicit.
- **Rejected:** Room. It is fine, but adds KSP and generated code for little gain here.

## ADR-006: JSON-schema subset validator

- Capability input schemas are generated by a small DSL that emits only these keywords: `type`, `properties`, `required`, `additionalProperties:false`, `enum`, `minimum`/`maximum`, `minLength`/`maxLength`, `items` and `maxItems`.
- The registry rejects any other keyword, so nothing is silently left unvalidated.
- A full JSON Schema library would add significant dependency weight to the APK.

## ADR-007: Connection keep-alive uses a `specialUse` foreground service

- The persistent gateway socket is not data sync. `dataSync` has a 6h/24h limit and cannot start from `BOOT_COMPLETED`, and the socket is not any other typed use.
- `specialUse` with a declared subtype is the honest type for a sideloaded app.
- The service is optional: the owner can disable remote connectivity, and local automations keep running through AlarmManager and WorkManager.
- Whether a foreground service keeps network access in Doze is ambiguous in the documentation. It will be measured on the device, and a battery-optimization exemption is requested explicitly.

## ADR-008: Explicit identity selection and bounded package inspection

Display labels are presentation only. New pairings allocate random principals; renewal selects the persisted invitation principal; reconnect requires owner selection of one stable agent ID. Existing credentials/grants are preserved. Package installation verification uses two bounded framework PackageManager queries rather than inferring metadata from truncated dumps. Raw dumps and arbitrary shell remain available for intentional diagnostics.

Gateway generations persist in socket attachments and Durable Object storage. In-flight routing remains bounded and transient; device SQLite remains the durable execution authority. A reconnect does not imply an old mutation should be submitted again.
