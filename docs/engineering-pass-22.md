## Changes

Startup now records required and deferred stages independently. A failed deferred backend observation, workflow-default check, history maintenance or schedule restoration does not prevent the remaining stages from running. Required database and execution-recovery failures remain explicit failures. The owner can retry only failed/interrupted deferred stages; this does not replay required recovery or erase state. The recovery page distinguishes saved Android access from an actually bound service, saved enrollment from an acknowledged gateway connection, and a Termux installation from accepted external execution. Notification reconnection is limited to SIConnect's own already-granted listener. Remote Full control does not confer owner repair authority.

Agent names can be edited independently of credentials and grants. The atomic update preserves unknown stored fields, Full-control restoration snapshots and token indexes; concurrent activity updates cannot overwrite it. The UI separates display name, identity and actual credential provenance. Rename drafts survive recreation, and cancelling leaves the saved grant unchanged. The legacy shared development identity is described as such rather than silently relabeled as a personal bot.

Three typed Clock tools retain durable per-agent timer identities before dispatch. They use a labeled native SET_TIMER intent and the exact installed handler, refuse existing Clock notification work, and cancel only an unambiguous, creator-bound published action for their own unique timer. This initial implementation supports Android's system user. It never adopts or globally dismisses arbitrary timers. Samsung publishes the exact label in its ongoing-notification extras but does not publish an independently verified countdown through these observations; accepted intent, observed notification, published cancellation and verified business outcome remain separate fields.

`messages.recent` navigates Google Messages on an owned private display, verifies the exact visible conversation label and thread header, locates the latest visible edge, and merges bounded older bubble windows only when their overlap is unambiguous. Every headless child uses the original agent, origin, backend and deadline and still requires its own policy authorization. Partial scans, unreadable/truncated content, uncertain scrolling and cleanup are reported explicitly. Opening a conversation may mark it read. This is visible app data, not direct SMS/RCS database or contact-identity verification.

`codex.execute` starts a fresh noninteractive run through the real same-agent `termux.execute` child. It passes the prompt as one argument, closes stdin, loads the existing login environment quietly, uses either an explicit npm JavaScript entrypoint through Termux Node or an explicit Android compatibility script, requests JSONL, and selects per-run full access to avoid the incompatible Linux sandbox. It does not change global configuration, saved authentication or running sessions. Existing rules/profiles/hooks still apply. Child approval, timeout, late callback, cancellation and uncertain output follow the existing durable Termux path; no guaranteed subprocess termination or external-task success is inferred. A read-only check found **zero configured Codex MCP servers**: this launcher does not pair Codex with SIConnect phone tools.

Completed ordinary recipe families now respect owner-enabled payload retention: safe leaves compact before parents, while bounded ancestry checks preserve active, uncertain, missing or protected workflow/proposal/reminder links. Permanent retry identities remain. This fixes completed Messages/Codex children otherwise retaining full snapshots indefinitely. Production retention remains disabled.

Original request observers subscribe before their initial database read and conflate matching updates, preventing a terminal result committed during that first read from being missed. The pattern is shared by recovery, private-workspace and approval views.
