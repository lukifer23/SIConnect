# Pass 21: bounded owner screens and native command reliability

November 7, 2026. Installed **0.6.0-dev.18 / code 26**, main SQLite schema **12**, Termux journal schema **1**, **104 phone capabilities / 105 MCP tools**. The compatible development signer and existing enrollment are preserved.

## Changes

Activity search now applies to metadata across the whole retained history, including compacted outcomes, before SQLite's page limit. It supports action titles, agent names, outcome labels and request IDs without decoding arguments or results. Literal `%`, `_` and SQL-looking text remain literal. Typing is debounced independently of live updates; sequential, conflated refreshes prevent ongoing agent work from repeatedly cancelling a search. History and selected-result loading have explicit error/retry states. An audit-only refresh cannot erase a missing-record error.

Schema 12 adds indexed reminder/automation display projections. Its migration streams existing rows, backfills metadata and leaves original JSON unchanged. Normal scheduler writes update JSON and projections atomically. Home reads three upcoming reminders, three enabled automations and three attention items rather than hydrating entire histories. Automations has global metadata search, state filters, 50-row keyset pages and 30-row run-history pages. Nullable legacy times remain visible and paginate correctly. Full schedule inputs and workflow results load only for the selected item.

Settings loads only its current data-backed page, including workflow definitions and enabled state in one query on IO. Loading and failure no longer look like an empty collection. Storage reads its saved policy before enabling changes and offers retry after a failed load. Workflow text, URLs and credentials survive Activity recreation in an ordinary RAM ViewModel, never an Android saved-state Bundle. Private-workspace checks retain their original request ID and reload its outcome after recreation without resubmitting; past readiness is timestamped and missing fields are unknown.

Termux waits now read the durable callback journal after their own wait deadline. A callback committed just before its in-memory notification can no longer be falsely reported missing. Parent cancellation/deadlines still propagate. The Codex saved-login check redirects the entire login-shell process, including profile startup output, before it can reach the execution journal. Exact argv and exit status are preserved.
